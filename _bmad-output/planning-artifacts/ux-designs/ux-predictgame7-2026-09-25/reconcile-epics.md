# Reconcile: epics.md vs UX spines (DESIGN.md / EXPERIENCE.md)

Scoped to the 4 new surfaces. Existing surfaces ratified as-is; gated/parked items excluded.

- **Story 4.1 AC (deep-link preload) — contradiction.** AC requires `/series/<id>?method=<slug>` to "render Predict preloaded with the series and method applied" on cold GET; Story 4.4's round-trip AC requires the same link to "reproduce the same series+method state on open." The spines route `/series/<id>` to the editorial series page and never mention the `?method` query param (no redirect, no CTA param carry). **Fix:** spec that the series-page Predict CTA inherits `?method` (and the series) into `/predict`, or record an owner decision that the editorial page is the intended landing — either way EXPERIENCE.md IA/State Patterns must address `?method` on series URLs.

- **Story 4.5 AC (editorial model: headline, images) — omission.** The content model carries `headline` and `images`, but DESIGN.md's series-page layout has no image treatment and the hero headline is specced as generated team words ("teams in words, not abbreviations") with no rule for when an editorial `headline` exists. **Fix:** add to DESIGN.md — editorial `headline` overrides/supplements the default hero headline; markdown/images render inside the longform column (styling, alt text, responsive width, AA contrast for captions).

- **Story 4.5 (video embed URLs, plural) / Story 4.6 ("at least one video embed each") — omission.** Spines spec a single "video embed + credit" section; the model allows multiple embeds. **Fix:** state whether multiple embeds stack in one section (each with its own credit caption) or the pilot convention is one-per-series.

- **Story 4.5 AC (embeds "appear in the prerendered HTML") vs EXPERIENCE.md lazy facade — tension.** The facade-until-play pattern must not strip the embed from JS-disabled/prerendered HTML (Stories 4.3/4.5, 4.7 drill fetches a flagship page with JS disabled). **Fix:** note that the facade markup itself (video title, thumbnail, creator credit, outbound link) is prerendered server-side and satisfies the AC; the iframe swaps in only on tap.

- **Story 3.3 ACs (contact inline errors + success state) — partial omission.** The pattern exists but EXPERIENCE.md scopes inline-field-error to "Invalid input on Predict custom form" only, and no form-success confirmation state is specced anywhere (the only success state is the share "Link copied." toast). Story 3.3 requires inline per-field errors on the contact form, the FR-8 invalid-input vs service-failure distinction there, and "a clear confirmation state" with screen-reader-announced status. **Fix:** broaden the inline-field-error component's Use column to all forms (Predict custom + Contact), and add a form-success confirmation pattern (replacement of the form region, `role="status"` announcement, onward path) to Component Patterns/State Patterns.

- **Story 1.3 AC ("invalid-input errors … pre-submission where possible") vs EXPERIENCE.md inline-error rule — tension.** Spine says errors appear "on submit (not on keystroke)", which forecloses pre-submission validation the AC asks for where possible. **Fix:** keep no-keystroke-errors as the default but allow pre-submission validation for deterministic constraints (e.g., score bounds) — inline hint or constrained input — so the AC's "where possible" is honored.

- **Story 4.2 (card contents: "teams, logos, year/round, method") — omission.** DESIGN.md's OG card layout (eyebrow, team blocks, VS, wordmark band) has no slot for the method slug, though the story text lists it; ACs only forbid prediction *outputs*, so method (an input) is permitted. **Fix:** either add a method eyebrow/label to the card template or record the omission as a deliberate design decision in DESIGN.md so FR-31 doesn't reopen it.

- **Story 4.6 AC ("flagship series are discoverable as such") / Story 4.5 `is_featured` — omission.** Spines spec the archive-overlay link row for series with content but never say what `is_featured` drives visually (Home featured cards, any archive marker). **Fix:** add one line mapping `is_featured` to the Home hotspot/featured-card selection and any archive affordance, so the flag has a defined UX consequence (Home surface itself stays ratified as-is).
