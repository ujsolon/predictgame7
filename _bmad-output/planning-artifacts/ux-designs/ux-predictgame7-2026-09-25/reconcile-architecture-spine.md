# Reconciliation — UX spines vs ARCHITECTURE-SPINE.md (2026-09-23)

Scope: DESIGN.md + EXPERIENCE.md (ux-predictgame7-2026-09-25) checked against binding ADs. Existing surfaces ratified as-is; gated/parked features not flagged.

- **AD-6 — copied share link bypasses the `share-og` hop.** EXPERIENCE.md Flow 1 (steps 2–3) has the Share button copy the raw deep-link (`/predict?custom=<base64>`) to the clipboard, then claims the chat renders the custom-matchup OG card. AD-6 is explicit that GitHub Pages meta is static and crawlers don't execute JS, so the link users copy must be the **`share-og` Edge Function URL** (`…/functions/v1/share-og?p=<payload>`), which serves per-prediction `og:title/description/image` to crawlers and redirects humans to the deep-link. A raw deep-link pasted into a chat yields only the generic fallback meta — Flow 1's climax cannot happen as written. **Fix:** spec the Share button (EXPERIENCE · Component Patterns + Flow 1) as copying the `share-og` URL, with the redirect landing on the deep-link; keep clipboard/native-sheet behavior otherwise unchanged.
- **AD-6 / FR-25 — `utm_source=share` attribution silently dropped.** Neither spine mentions that the `share-og` redirect appends `utm_source=share` (FR-25 share attribution), nor that landing URLs may carry it. UX copy/analytics behavior around share landings is unspecified. **Fix:** add one line to EXPERIENCE · State Patterns or Component Patterns acknowledging the attribution param on arrival from shares (and that it must flow through the AD-1 analytics layer only, never a second tracker).
- **AD-2 / AD-6 — `SharePayload` schema ownership unmentioned.** Both spines reference `/predict?custom=<base64>` but never state that the base64 payload follows the `SharePayload` schema owned by `supabase/functions/_shared/contract.ts`, which exists so the Share button and `share-og` can't diverge. **Fix:** note in EXPERIENCE · Component Patterns (Share button / OG card rows) that both ends derive the payload from the single contract schema — a UX-visible constraint (one link shape, one card per link).
- **AD-9 / Consistency Conventions (Errors) — retry panel vs ratified toast pattern.** AD-9 ratifies "inline try/catch + console.error + sonner toast" as the UI error pattern; UX introduces a persistent retry panel that explicitly replaces the toast for service failures ("not a toast"). This is a defensible refinement (retry panel is a treatment, not a new state library), but as written the two documents disagree on the default error surface. **Fix:** add one sentence to DESIGN.md · Components (retry-panel) or EXPERIENCE · Component Patterns stating the panel is the deliberate replacement for toasts on re-attemptable fetch/mutation-result regions, with sonner retained for one-off mutations — and flag AD-9 for a companion note at implementation time.
- **AD-9 — RHF + zod for new forms silently dropped.** EXPERIENCE specs inline field errors on the "Predict custom form" (submit-time validation, clears on valid re-submit) but never names react-hook-form + zod, the AD-9 standard for new forms; the described behavior is compatible (zod resolver on submit) but the constraint is unstated for implementers. **Fix:** add to EXPERIENCE · Component Patterns (inline-field-error row) or Foundation: new/changed forms (incl. the custom-matchup form) use RHF + zod per AD-9; error timing follows the resolver, not keystroke linting.

**Verified consistent (no action):** shareable URL shapes `/series/<id>?method=<slug>` and `/predict?custom=<base64>` (AD-6, EXPERIENCE · IA); OG rendering server-side only in the `share-og` function, never a client component, `@vercel/og` (AD-6, DESIGN · Components); 404 treatment for unknown series via the SPA `404.html` fallback (AD-6/AD-7, EXPERIENCE · State Patterns); series page bakes facts only, no prediction outputs (AD-7); Radix/shadcn + sonner stack (AD-9, both spines); platform share buttons rejected partly for third-party tracker leakage — consistent with NFR-V1/AD-1 analytics isolation (EXPERIENCE · Anti-patterns).
