# Spec: Story 2.13 — ESPN feed adapter (the source change Story 2.6's egress evidence forces)

## Why

A pain to solve, with the same calendar deadline attached to it. Story 2.6 shipped the cadence — daily inseason runs, two offseason edges, a failure that files a deduped GitHub issue — and every part of it was proven working except the one part that has to leave the building: the fetch. `stats.nba.com` refuses all cloud egress (0/15 across two providers and three client stacks) and `cdn.nba.com` returns `403` from both clouds, so the scheduled source shipped in 2.4 answers to nobody but a residential address. `site.api.espn.com` answers from both clouds — 226 ms from Supabase, 78 ms from a GitHub-hosted runner, confirming run `37119291248` — which is why FR-21 was re-resolved on 2026-10-03 (`sprint-change-proposal-2026-10-03.md`, owner calls C1–C4) and why the documented reopening trigger on the feed route has fired.

This is a **source change, not a cadence change**: the bracket, the three-line cron shape, the notify composite, the dedupe, the concurrency group and `--require-feed`'s design all stay exactly as 2.6 shipped them, and D-7 stays closed. The one exception, made by the owner on 2026-10-04, is the *minute* — `09:30 UTC → 07:30 UTC`, with `keepalive.yml` moving to `07:00` so the ordering reason D-5 actually recorded survives the move rather than being inverted by it (`schedule-amendment.md`). Affected: the Apr–Jun 2027 window, where stale Active Series invalidate the traffic measurement the whole plan rests on; the owner, who is the only reader of the signal and the only party allowed to run a live fetch; and the `teams` table, which gains its first per-provider identity column (`00018`, applied 2026-10-04).

## Capabilities

- **CAP-1**
  - **intent:** An `espn` adapter sits behind the `SeriesDataSource` port and becomes the scheduled source, with `nba_com` displaced from the workflow surface but still recognised.
  - **success:** `espn` is in `ADAPTER_REGISTRY`, in the `SERIES_SOURCE`/`--source=` vocabulary and in `seriesdatasource-port.md:82`'s registry line; `--source=nba_com` still resolves and runs by hand; both workflow files carry no `nba_com` on the scheduled path; `npm run gate` exits 0. See `surface-inventory.md`.
- **CAP-2**
  - **intent:** One scoreboard fetch per run yields the port's two row shapes, keyed the way the database keys them.
  - **success:** Against a committed fixture of a measured payload, `fetch_series_statuses()` and `fetch_game_scores()` return rows keyed on `(year, team_a_id, team_b_id)` with game numbers in 1..7 and no tie (from `espn` only 7 ever qualifies — CAP-6); `--dry-run` writes nothing; a second real run changes nothing; a missing secret names the secret rather than surfacing as a fetch error. Measured on ESPN's own bytes: the `20250503` capture replays to exactly one status row and one score row, and the `20250504` capture admits its Game 7 with the **away side as winner** (`winner_team_id = team_b_id`) while naming the Game 1 it drops.
- **CAP-3**
  - **intent:** A team in the feed resolves to exactly one `teams` row through that provider's own code, or the run stops.
  - **success:** Migration `00018`'s `teams.espn_code` resolves `NY` → the Knicks row (id 20) and `SA` → the Spurs row (id 27) — two of the **six** measured divergences from `teams.abbreviation`, the others being `GS`→GSW, `NO`→NOP, `UTAH`→UTA, `WSH`→WAS (full table and provenance: `payload-contract.md`; finding 5 first flagged `NY`/`SA`). An event team whose code matches no row aborts the run **naming the code**, and that abort walks every event *before* admission — so a regular-season game carrying an unseeded code stops the run too. No test or fixture resolves a team by substring, city, nickname, `displayName` (`LA Clippers` on one route where `00005` stores `Los Angeles Clippers`) or ESPN's own `team.id` (which differs from `teams.id` on 27 of 30).
- **CAP-4**
  - **intent:** A game's round and game number come from what the feed actually prints, and the archive's own vocabulary is left alone.
  - **success:** `competitions[0].notes[0].headline` parses into the canonical round label and the game number — measured spellings: `East 1st Round - Game 2`, `NBA Finals - Game 2`, `West 1st Round - Game 7`, `East Semifinals - Game 1`. A headline that is **absent** (a regular-season event carries no `notes` array at all) or does not match `"<round> - Game N"` (proof D's `NBA Canada Games 2026`) excludes that game and **names the exclusion** in `describeRun`; no round spelling is ever invented to admit one, and no unparseable headline raises an error either. The 17 archived era spellings are not rewritten by anything in this story.
- **CAP-5**
  - **intent:** The date the adapter asks for is the day the games were actually played, in the league's own timezone.
  - **success:** A unit case pins the boundary — a run instant of `2026-06-06T07:30:00Z` requests `dates=20260605`, because ESPN filters by US local date and the measured game stamped `2026-06-06T00:30Z` lives under the *previous* local day (finding 4). The pinned instant is the amended cron minute; the answer is the same ET day it was at 09:30, which is the point of pinning it. A UTC-derived date is a bug this test catches. The same derivation was exercised from a runner by run `37235646137`, which asked for `dates=20261003`.
- **CAP-6**
  - **intent:** Only a finished Game 7 reaches the plan, and a shape nobody has ever observed cannot smuggle itself in.
  - **success:** A fixture carrying `status.type.state == 'in'` with a plausible score produces zero writes and one named exclusion, and so does a `Final` game whose headline parses to Game 1–6; the admit rule is `Final` **and** game 7, and anything unrecognised is excluded **by rule** rather than defaulted to a guess. The 3–3 certification is not dropped: `pipeline_complete_series` re-reads the six stored games and raises unless they split 3–3 (`supabase/migrations/00015_pipeline_series_functions.sql:286-308`), so a one-row source cannot fabricate a series. Only `state == 'post'` and `description == 'Final'` have ever been fetched, so this is the substitute for a probe — recorded as such, not as a measurement.
- **CAP-7**
  - **intent:** The empty-feed alarm 2.6 built keeps working against the new source without its design moving.
  - **success:** The adapter declares `describeRun` with `feedSeriesCount` counted **before** any adapter-side exclusion and `hasRunReport: true` in the registry; `--require-feed` against a fixture whose `events` is empty exits non-zero naming the flag and the adapter, and the same flag against `manual_csv` still refuses up front. A rest day therefore also goes red, by owner decision. Measured on a non-playoff day, both on the owner's shell (a regular-season night: `15 series in feed … 15 unreadable headline`) and on the runner (run `37235646137`: `1 series in feed … 0 Game-7 candidate(s)`), the count stays non-zero through total exclusion — which is what keeps a no-playoff night from false-alarming.
- **CAP-8**
  - **intent:** The adapter is exercised against a real recent playoff payload, and the code table that seeds `00018` is produced by that exercise rather than asserted.
  - **success:** **OBTAINED 2026-10-04.** The 30-franchise ESPN code table exists as measurement, and every `espn_code` in `00018` traces to a line of the committed capture `tests/pipeline/fixtures/espn-teams-site-20261004.json` read by the probe's own reader — not to a guess list; `espn-adapter.test.ts` re-reads the migration's `UPDATE` statements against those bytes on every `npm test`, so the seed cannot drift silently. Measuring it **falsified** this spec's own "assumed to agree" row: 24 of 30 codes equal `teams.abbreviation` and 6 diverge. `scripts/probe-espn-adapter.mjs` stays the owner-run live leg in the Story 2.4 precedent — stateless, non-zero on a shape it cannot read, re-runnable in 2027: legs A and C obtained on live JSON 2026-10-04, and its reader now runs offline under `--fixture-teamlist=`. A probe re-run from the scheduled environment is a **confirmation** leg, not a discovery leg.
- **CAP-9**
  - **intent:** If the ESPN route breaks, the next source is already named and the floor is already there.
  - **success:** The adapter's doc block records basketball-reference as the designated automated fallback of last resort (measured reachable from both clouds, `200` HTML, ~220 ms — scrape cost, unimplemented) and `manual_csv` as the floor, in the port doc and in `failure-modes.md` mode 2's re-pointed wording.
- **CAP-10**
  - **intent:** The four proof obligations Story 2.6 transferred out get executed against the new source instead of being inherited as a permanent debt.
  - **success:** All four dispatches in `run-sheet.md` carry a recorded run id — including the green **non-dry** run of the scheduled source that `spec-2-6`'s CAP-2 still owed. **All four OBTAINED 2026-10-04:** `37199559809` (fantrax zero-write), `37202299383` → fresh issue #9 (dedupe resets on close), `37201495284` (the Docker rehearsal on a runner), and `37235646137` (green non-dry `--source=espn --require-feed`). The fourth is the hollow green the owner accepted, and its log is the arithmetic: `1 series in feed … 0 Game-7 candidate(s)`, then `plan: 0 birth(s), 0 completion(s), 0 skip(s)` and `applied: 0/0/0`. It proves hosted fetch → plan → exit 0; it is **not** a write proof, and the record says so — the write half is step E, Story 2.7's simulated-playoff-week drill.

## Constraints

- **The parameter form is fixed by measurement, not preference:** the endpoint is `…/sports/basketball/nba/scoreboard?dates=YYYYMMDD`, one date per request. A range is refused by the host (`400` with a JSON error body, `dates=20260601-20260608`, re-measured 2026-10-04), so a backfill is a bounded loop of single-date requests and never a new parameter. `seasontype`/`playoffType` are out of scope: unmeasured, and one-date-per-run is already the cadence's shape.
- **`teams.espn_code`, not `team.abbreviation`, is the join key** (finding 5, now measured on all 30 franchises rather than on the two that were sampled). No substring, city, nickname, display-name or provider-`team.id` match is admissible anywhere in the adapter — the one item in the evidence with a real silent-failure mode, since a mismatch drops games. An adapter built on the pre-measurement assumption would have aborted every Warriors, Pelicans, Jazz and Wizards game with `unknown ESPN team code` while looking correct in review.
- **`00018` is additive, nullable, unique-where-not-null, and seeded for the 30 modern franchises only.** The 29 historical identities in `00007` and the `Team A`/`Team B` placeholders stay NULL; they cannot appear in a 2027 playoff feed, and a code that does resolve to nothing aborts the run instead of being curated into a row. `EXPECTED_TEAM_COUNT = 59` is untouched because no row is inserted. It was rehearsed first (`COVERED_THROUGH` extended through `00018`; exit 0 locally and on a runner — push-triggered run `37235181319`, section 7 in full), `docs/CURRENT_DATA_MODEL.md` landed in the same commit, and the owner **applied it with `npx supabase db push` on 2026-10-04**. The agent never runs `db push`, `db reset` or `db start`, and never points `psql` at `supabase/.temp/project-ref` — that *is* production.
- **The runner stays date-blind.** The single date is derived from the run instant in `America/New_York` inside the adapter — a fetch-scope rule, never a state rule. It is *always* "the previous calendar day in ET" and never a fixed constant: there is no "first playoff date" the adapter can be pointed at, because naming one would be the calendar logic Non-goals refuse. No Apr–Jun branch or postseason calendar enters `run.ts` or `plan.ts` (AD-4, Story 2.4 Decision 2). The bracket, the window's three-line shape, the `--require-feed` placement, the notify composite, the dedupe and the concurrency group are not touched.
- **The scheduled minute moves, and the keepalive moves with it (owner call 2026-10-04).** `09:30 UTC → 07:30 UTC` on the three `pipeline-inseason.yml` lines and both `pipeline-offseason.yml` edges, and `keepalive.yml`'s `0 9 * * *` → `0 7 * * *`, so the run stays *after* the warm-up ping. D-5's only stated reason for the slot was that ordering (`decisions.md:65` — "so a sleeping instance is not made this cadence's failure mode"), and the pipeline reads and writes through the same PostgREST endpoint the keepalive pings; moving the pipeline alone would invert the reason rather than keep it. Nothing else in the schedule moves, and `decisions.md`/`failure-modes.md` gain an amendment line rather than a rewrite. See `schedule-amendment.md` for the margin this trades away.
- **One date per run, rest days included.** The owner declined a lookback window: deciding feed emptiness across several days would let the adapter inflate the number `--require-feed` reads, which is the independence Story 2.6 D-3 bought. A legitimate playoff rest day therefore files a red run, and that red is the instrument working.
- **Round naming comes from the headline because there is no typed field:** `competitions[0].type.shortName` is absent on the measured payload (finding 2, re-confirmed on the committed captures).
- **A dated request is not known to carry only playoff series.** `competitions[0].notes` is a **playoff-only** field — a regular-season date returns events with no `notes` at all — and the first scheduled-environment read returned an *exhibition* Final (`NBA Canada Games 2026`, `TOR/MIA`) that belongs to no series this product models. So admission must stay a headline-pattern rule and never a count of what came back, and an unreadable-headline exclusion must still leave `feedSeriesCount` non-zero.
- **The scheduled feed completes; it does not seed** (owner call 2026-10-04, mid-build). Admission is `Final` **and** Game 7, so `plan.ts` learned exactly one new source shape — a stored *pending* series plus a source carrying only that series' game 7 — and the games 1–6 the same payload prints are excluded alongside the unfinished ones. Consequence stated rather than discovered later: the April offseason edge can no longer initialize the bracket from this feed, so births belong to `--source=manual_csv` and Story 2.7's drill.
- **Every live leg is owner-run.** No test fetches the network; adapter tests read committed fixtures, so the suite stays hermetic on a runner that has no reason to reach Disney. **One recorded release:** the owner authorized four read-only GETs from their own machine on 2026-10-04, and the bodies are committed byte-for-byte under `tests/pipeline/fixtures/`. That release was needed because this machine's UDP/53 path answers `RCODE_REFUSED` for `site.api.espn.com` (a filtering resolver — the feed is exonerated by measurement, not assumption), and it superseded this sheet's claim that a one-off hosted-runner dispatch was "the only shape available".
- **`nba_com` is not deleted** (C1): the registry keeps the name and its refusal-free run path, because dropping a recognised name invites a future session to re-propose the endpoint unexamined.
- Nothing in `supabase/functions/**` moves and no Edge Function is deployed; no new PostHog event names; no new RPC, grant, or row-level policy beyond the `00018` column; the archive stays frozen so no stored `round` spelling is rewritten.
- **A shape drift must fail loudly.** `site.api.espn.com` is undocumented Disney-side infrastructure with no SLA, so no parse may default a missing field to a plausible value — a drifted payload exits non-zero and lands in 2.6's proven issue machinery. Connection failures are no exception: `describeFetchThrow` (`espn.ts:216`) unwraps `error.cause` so a fetch failure names its class (`ENOTFOUND` vs `ECONNREFUSED` vs a TLS-named code) instead of printing a bare `fetch failed`.
- `npm run gate` is the definition of done, its exit code read from the command itself and never from a pipe. Commits are local to `master` with named files, `git status` re-checked first (parallel sessions on this tree); the agent never pushes and hands over the command instead.

## Non-goals

- Building the basketball-reference scraper. The designation is recorded; the implementation is a conditional story authored only if the ESPN route breaks (C4).
- Changing the **bracket**, the window's three-line shape, the alarm wiring, the credential handling, or `--require-feed`'s design — 2.6's shipped and proven half, and this story's premise is that the blocker was the source. (The scheduled *minute* is the single exception, and it moves the keepalive minute paired to it — owner call 2026-10-04, argued in `schedule-amendment.md`, not a build-time discretion.)
- Any multi-date fetch, range parameter, or calendar logic that knows which days the playoffs fall on.
- Curating `espn_code` for historical franchises, or backfilling the 1948–1997 archive.
- Retiring `nba_com` or removing `manual_csv`. (`keepalive.yml`'s cron is the one line here that *does* move, to `0 7 * * *`, by the owner's own 2026-10-04 call argued in `schedule-amendment.md` — nothing else in that file changes.)
- Any PLANNED-GATED scope (accounts FR-22/23, betting-adjacent FR-26–29, video FR-13) and any new analytics event.

## Success signal

On a morning inside the Apr–Jun 2027 window, a run nobody typed fetches ESPN's scoreboard for the date the games were actually played, resolves all six divergent codes (`NY`, `SA`, `GS`, `NO`, `UTAH`, `WSH`) to the right rows, appends a real Game 7 to a pending series through the existing RPCs — or refuses loudly and files one deduped issue naming what it could not read — and `/predict` shows an Active Series that is not stale. The same cadence on a rest day goes red on an empty feed, and that red is the alarm working rather than a defect. Half of this is already demonstrated: run `37235646137` is a hosted, non-dry, exit-0 `espn` run through the shipped adapter and the applied column, accepted **hollow** by owner call. The write half is not: it is proven by Story 2.7's drill (step E) and by the 2027 window, not by a unit test.

## Assumptions

- The three payload classes now measured — regular-season events with **no `notes`**, playoff events carrying `"<round> - Game N"`, and one exhibition event carrying a `notes` headline that matches nothing (`NBA Canada Games 2026`) — are the classes the 2027 bracket will carry. What is assumed is narrower than the original line: that no fourth class arrives shaped like a playoff headline, since a headline inside the closed vocabulary is what would be *admitted* rather than excluded-and-named. A new non-matching class costs a missing row, not a wrong write. **Accepted by owner call 2026-10-05, residual named rather than closed:** the backstop for an impostor headline that parses is the server-side 3–3 re-read in `pipeline_complete_series`, and no year/season sanity check is added to the admit rule — it would collide with the date-blind constraint and is not authorised here.
- ESPN's codes are stable between the 2026-10-04 capture and the 2027 window. They are now measured for all 30 modern franchises (24 equal to `teams.abbreviation`, 6 divergent — `payload-contract.md`), so what remains assumed is that the provider does not re-code a franchise mid-window. The seed's own guards and the abort-naming-the-code path are the detectors: a re-coded franchise stops the run rather than silently dropping its games. Left as-is by the same 2026-10-05 call, and nothing in this story pre-authorises the in-season fix path.
- No game is still **in progress** at the amended 07:30 UTC instant. At that hour it is 02:30–03:30 in `America/New_York`, so a 10:00 pm ET tip that reaches triple overtime would be excluded as non-Final by CAP-6, named in `describeRun`, and never re-fetched — a missing row with a green alarm. Margin under 09:30 was about four hours; `schedule-amendment.md` records what the owner traded, and Story 2.7's row-count-vs-bracket read stays the detector. **Re-priced and kept by owner call 2026-10-05** — the slot stands with the 30–90 minute margin accepted knowingly.
- The GitHub-hosted → ESPN cell keeps answering. It is now measured through the shipped adapter on a runner (`37235646137`, on top of `37118226487` and `37119291248`), so what remains assumed is only that playoff-season payload volume and June traffic do not change the class of failure — and that class is 2.6's alarm, not a silent stale.

## Open Questions

- Which round spellings does a full postseason actually print? Four are measured (`East 1st Round`, `West 1st Round`, `East Semifinals`, `NBA Finals`) — including a real `West 1st Round - Game 7`, which was the parseable-through-seven-games half of the original question. Still unmeasured: a Conference Finals spelling, and whether any playoff headline names the teams instead of the round. Both are gated by rule — an unknown round phrase is excluded and named, never admitted with an invented spelling — so only the 2027 window can tell whether the closed vocabulary in `adapters/rounds.ts` covers the calendar.
- What does a Game 7 at a neutral site, or under an arena rename, produce in `venue.fullName`? It was present on every measured sample and this story never reads it, but Story 2.8's venue semantics make a wrong assumption here expensive.
- How many rest-day reds will the Apr–Jun window produce, and will one of them be read as the alarm being broken? Not measurable now; Story 2.7's drill is the first full-week read of the cadence.
- Does an unfinished game ever print a `status.type.state` of `in` or `pre`, or a `description` other than `Final` (`Final (OT)`, `Final 2OT`)? There is no unfinished NBA game to fetch in October 2026, so CAP-6 admits only the two strings ever observed and everything else is excluded by rule. The probe leg is the only leg that can see a real `state == 'in'` payload, which means the 2027 window is when this stops being a rule and becomes a measurement.
- *Resolved 2026-10-04 — the run-sheet step D question.* Owner call: a hollow green is acceptable, so the dispatch fired on a day the owner named (`37235646137`) and behaved exactly as predicted — one series in feed, zero candidates, nothing written — while the write half moved to Story 2.7. Left open only in a narrower form: if a future proof ever needs a non-hollow green, the dispatch surface has no date input and adding one is a separate authorisation, not part of this story.
