## 4. NFR-P1 latency, both halves

- **Threshold being compared to:** the provisional bar is **P95 ≤ 3 s for a full request on a mobile 4G connection** (`ARCHITECTURE-SPINE.md`, carried into `epics.md` as "noted against the provisional 3s P95").
- **Deployed function confirmed current first**, as Decision 4 requires: `predict-game-7` was redeployed 2026-09-28 and re-probed to all 11 contract keys (`deferred-work.md`, the deploy-blocker entry), and every response in this run carried all 11 keys (§2.1, §2.3) — so the timings below are the committed code's, not a stale deploy's.
- **Server half — 20 sequential probes** through the Edge Function: `computation_time_ms` between **1 and 5 ms**; wall-clock (fetch wrapper `performance.now()` delta, request→response parsed) **min 322 ms / median 496 ms / max 1324 ms**.
- **Server half, re-run 2026-09-29 as a proper 24-sample study** (6 per method, all four `MethodSlug`s, plain Node `fetch` — no browser, no DevTools, no curl): every response conforming, all 11 contract keys present, `method_used` echoing the requested slug. Wall **min 332 / p50 503 / p95 1022 / max 1475 ms**; `computation_time_ms` **min 4 / p50 4 / p95 5 / max 6**. Cold (first 4) **p50 952 / p95 1475** vs warm (rest) **p50 477 / p95 827** — the tail is Supabase edge cold-boot, not the maths. This is the percentile the bullet above refused to claim.
- **…and re-run a third time 2026-09-29 through the committed tool** (`npm run perf:predict -- --server-only`, same 24 samples): wall **min 245 / p50 435 / p95 764 / max 2021 ms**; `computation_time_ms` **min 1 / p50 4 / p95 5**; 24/24 conforming, 11 keys. The median and compute reproduce within noise; the p95 differs because in *this* run the cold-boot penalty was one concentrated sample (2021 ms, the very first request) with all 20 warm samples under 765 ms, whereas in the earlier run it was spread across the first round — p95 of 24 picks the second-highest value, so it lands on 764 here and 1022 there. The shape is identical across both runs — **cold (first round) p95 2021 vs warm p95 734, ~2.7×, same conclusion as above**, and the maths stays under 6 ms. The original study's producer was a throwaway script in temp; that gap is closed, so both numbers now come from a file in the repo.
- **Client half — original observation, now superseded:** desktop custom run 2151 ms and 2165 ms; mobile historical run **4545 ms**; a mobile custom run whose fetch resource duration was 4372 ms.
- **Client half, re-run 2026-09-29 under real throttling** (`scripts/measure-predict-latency.mjs`, `npm run perf:predict`): headless Chrome over CDP at **390×844**, `Network.emulateNetworkConditions` = DevTools **Slow 4G** (562.5 ms latency, 184 KB/s down, 84 KB/s up) plus `Emulation.setCPUThrottlingRate: 4`. **23 samples** (3 cold = fresh navigation + full picker selection each time; 20 warm = selection kept, Generate re-activated).
