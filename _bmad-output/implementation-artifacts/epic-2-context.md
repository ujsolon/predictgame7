## Goal

During the 2027 playoff window, Active Series reflect the latest results with zero manual editing, and the epic still completes even if every automated data source fails — a spreadsheet-fed floor is a valid end state. The epic first closes the server-side quality gate (CI type-check of the Edge Functions plus request-boundary validation, so a malformed request fails with a real 400 instead of a plausible wrong answer), then puts the series identity key and the derived phase into the schema and read path, builds the pipeline runner behind a swappable data-source port, implements the automated adapter the spike selected, refreshes the insights cache from the archive, and schedules everything on CI workflows with loud failure. Calendar-critical: automation must be deployed and drilled before April 2027, because stale Active Series would invalidate the release's own traffic measurement.

## Requirements & Constraints

- Active Series appear distinctly from Historical entries and reflect the latest pipeline run; they change only on pipeline cadence. Live/in-game scoring is permanently out of scope. Offseason, the Active group must be empty-but-non-breaking, never an error.
- Archive data stays canonical and internally consistent; every pipeline run is idempotent — re-running identical input changes nothing. Legacy tables stay archived, never deleted.
- Offseason mode initializes/finalizes the postseason bracket idempotently at playoff start and end; inseason mode runs daily inside a configurable window.
- Insight pattern-card values are recomputed server-side from the archive into the cache; no insight arithmetic in the browser.
- A failed run is detectable without a human watching: non-zero exit, workflow-failure notification within one cron cycle, logs sufficient to diagnose without local reproduction. If the spreadsheet floor is the inseason source, a documented daily operator cadence (CSV edited before the daily run slot) replaces the cron guarantee.
- Service-role credentials come only from CI/secret storage — never committed, never in client-visible env. Client code reads through the single anonymous client; all writes stay in Edge Functions or pipeline scripts. RLS stays on.
- Free-tier ceilings stay accepted constraints; existing keepalive workflows are extended alongside, never modified.
- Schema change and read-path flip ship in one release, outside a playoff window, with the schema documentation updated in the same commit; production applies only on the owner's explicit go-ahead, after rehearsal in a throwaway database.
- Every story ends with the four-command local gate green; type-checking of Edge Function entry points exists only in CI, and function deploys are ungated locally — probe the deployed function over the wire before blaming client code or calling a story done.
- Product guardrails hold: no wagering, odds, or guaranteed-pick mechanics; no accounts or other Traffic-Gate-blocked surfaces.

## Technical Decisions

- A series' phase is derived, never stored: a null winner means Game 7 pending, a filled winner means archive. Rows are born only at a certified 3–3, atomically with their six score rows, and complete by appending game 7 plus the winner in one write. The vestigial stored status column, its check constraint, and its default are dropped; every consumer reads one shared helper instead. No code may derive phase from dates or row-creation timestamps.
- Integrity is convention plus a defensive read, not the database: the runner asserts the derivation's invariant before committing and exits non-zero; the read path excludes and reports a series that does not reconcile rather than guessing it into a group. No DB trigger; a real observed drift reopens the question.
- Series identity is a plain column `UNIQUE (year, team_a_id, team_b_id)` — chosen over an expression index or generated key because it stays addressable by the client's upsert conflict target. `round` is deliberately outside the key with no check constraint: measured against the live table, `(year, round)` collides in 19 groups / 21 extra rows of 178, and round carries 17 era-dependent spellings, so keying or gating on it would tie idempotency to free text. The adapter owns the round vocabulary, deriving one canonical display value for new rows and never rewriting archived spellings.
- The team slots carry a convention, not an enforceable order: ~~the first slot is game 1's home team in all 178 measured rows~~ **corrected 2026-10-01: the first slot is the series *winner*** — on 177 of the 178; measured 2026-10-02 the `2026` Western Conference Finals stores `team_a = OKC` (game 1's home) with the winner in slot two, so the durable convention is `plan.ts:190-197`'s (slot one = game 1's home team), and the winner-slot reading is specific to `00007`'s backfilled block. ## UX & Interaction Patterns

- With nothing pending, the picker shows an empty, non-breaking Active group carrying the established empty-state line ("No active series right now — the next Game 7 is coming.") and an onward link to the archive.
- Active versus Historical separation is visible to users but has no stored flag: a series enters the Active group because it has six score rows and no winner, and leaves it on the single write that fills the winner.
- The pending-Game-7 highlight on the home surface is a rendered block, not a route; this epic proves only that the data reaches it. Its visual treatment, copy, accessibility floor and responsiveness belong to the sharing epic.
- Verification exercises the derivation with real data shapes rather than faked status fields, and notes the picker query is unfiltered — a seeded row is live to every visitor the instant it exists, so drill data is inserted deliberately.
