# Epic 2 Context: Playoff-Current Active Series

<!-- Compiled once from planning artifacts. Hand-maintained from here: edit freely and re-check against the planning docs when they change. No regeneration script exists. -->

## Goal

During the 2027 playoff window, Active Series reflect the latest results with zero manual editing, and the epic still completes even if every automated data source fails — a spreadsheet-fed floor is a valid end state. The epic first closes the server-side quality gate (CI type-check of the Edge Functions plus request-boundary validation, so a malformed request fails with a real 400 instead of a plausible wrong answer), then puts the series identity key and the derived phase into the schema and read path, builds the pipeline runner behind a swappable data-source port, implements the automated adapter the spike selected, refreshes the insights cache from the archive, and schedules everything on CI workflows with loud failure. Calendar-critical: automation must be deployed and drilled before April 2027, because stale Active Series would invalidate the release's own traffic measurement.

## Requirements & Constraints

- Active Series appear distinctly from Historical entries and reflect the latest pipeline run; they change only on pipeline cadence. Live/in-game scoring is permanently out of scope. Offseason, the Active group must be empty-but-non-breaking, never an error.
- Archive data stays canonical and internally consistent; every pipeline run is idempotent — re-running identical input changes nothing. Legacy tables stay archived, never deleted.
- Offseason mode initializes/finalizes the postseason bracket idempotently at playoff start and end; inseason mode runs daily inside a configurable window.
- Insight pattern-card values are recomputed server-side from the archive into the cache; no insight arithmetic in the browser.
- A failed run is detectable without a human watching: non-zero exit, workflow-failure notification within one cron cycle, logs sufficient to diagnose without local reproduction. If the spreadsheet floor is the inseason source, a documented daily operator cadence (CSV edited before the daily run slot) replaces the cron guarantee.
- Service-role credentials come only from CI/secret storage — never committed, never in client-visible env. Client code reads through the single anonymous client; all writes stay in Edge Functions or pipeline scripts. RLS stays on.
- Free-tier ceilings stay accepted constraints; existing keepalive workflows are extended alongside, never modified.
- Schema change and read-path flip ship in one release, outside a playoff window, with the schema documentation updated in the same commit; production applies only on the owner's explicit go-ahead, after rehearsal in a throwaway database.
- Every story ends with the four-command local gate green; type-checking of Edge Function entry points exists only in CI, and function deploys are ungated locally — probe the deployed function over the wire before blaming client code or calling a story done.
- Product guardrails hold: no wagering, odds, or guaranteed-pick mechanics; no accounts or other Traffic-Gate-blocked surfaces.

## Technical Decisions

- A series' phase is derived, never stored: a null winner means Game 7 pending, a filled winner means archive. Rows are born only at a certified 3–3, atomically with their six score rows, and complete by appending game 7 plus the winner in one write. The vestigial stored status column, its check constraint, and its default are dropped; every consumer reads one shared helper instead. No code may derive phase from dates or row-creation timestamps.
- Integrity is convention plus a defensive read, not the database: the runner asserts the derivation's invariant before committing and exits non-zero; the read path excludes and reports a series that does not reconcile rather than guessing it into a group. No DB trigger; a real observed drift reopens the question.
- Series identity is a plain column `UNIQUE (year, team_a_id, team_b_id)` — chosen over an expression index or generated key because it stays addressable by the client's upsert conflict target. `round` is deliberately outside the key with no check constraint: measured against the live table, `(year, round)` collides in 19 groups / 21 extra rows of 178, and round carries 17 era-dependent spellings, so keying or gating on it would tie idempotency to free text. The adapter owns the round vocabulary, deriving one canonical display value for new rows and never rewriting archived spellings.
- The team slots carry a convention, not an enforceable order: ~~the first slot is game 1's home team in all 178 measured rows~~ **corrected 2026-10-01: the first slot is the series *winner*** — there is no canonical id ordering, so the constraint cannot enforce slot direction. The runner asserts the pair is absent in either slot order before inserting (non-zero exit), and Story 2.3's plan additionally asserts `team_a_id` equals game 1's `home_team_id` so no adapter can slip the convention (Story 2.4 still owns the seed→slot mapping). **Qualification measured in Story 2.3:** the archived score rows carry no venue data — in 177 of the 178 series every game names the same team as home (the series' `team_a`), and in none do they name `team_b` throughout — so the 178/178 figure proves the archive was written from the slot convention, not that the convention matches real game-1 venues. Story 2.4 must decide whether its adapter's true home/away data reconciles against those rows or is normalised into them; see `docs/CURRENT_DATA_MODEL.md`. **Decided 2026-10-01 (Story 2.4, Decision 11, owner call 2A): the archive is frozen — no reconciliation and no normalisation.** The shipped `nba_com` adapter never re-ingests a historical postseason: it fetches only the one derived from the run's UTC date (`--season=` drills), so archived years stay out of the plan by fetch scope, and Story 2.3's archive guard (`plan.ts:382-390`) is the enforcement point that aborts a disagreeing drill rather than rewrite it. **RESOLVED, and it falsifies the convention as stated (2026-10-01, from the committed source data, not the live table):** the loader mapped `team_a = "Winner Team"` and 00007 wrote `home_team_id = team_a_id` for all seven games, so **the archive's `home_team_id` is the series winner and any whole-table Game-7 home-court statistic returns exactly 100%.** The audit's "178/178 = game-1 home" reading restates the backfill's own SQL rather than measuring it. Full write-up and the league reconciliation in `docs/CURRENT_DATA_MODEL.md` ("The archive carries slots, not venues"). Consequences for this epic: **Story 2.5 cannot compute `home_team_stats` from archived rows at all**; Decision 11's freeze is lifted once, by course correction, for a Game-7-home-venue backfill of the 160 NBA/BAA series (owner calls 2026-10-01: store three league values `NBA`/`BAA`/`ABA`; venue Tier B ships *before* 2.5; the archive shows a league chip/filter). Games 1-6 venues and any normalisation of archived scores stay out of scope, and the freeze stays in force for the ongoing pipeline.
- Measured archive facts, pinned: 178 series, 1,246 score rows, every series exactly seven, zero anomalies. The three circulating counts mean different things — 177 is the unreconciled source-spreadsheet figure, 178 is the live table, and the 172+5 split is a prerender-route count one short; route lists and reconciliations assert against the measured 178, never arithmetic on older figures. The uniqueness audit is re-run as the migration's pre-flight, and the migration is rehearsed through a full ordered replay to confirm the older backfill's conflict target still resolves at its own point. **The 177/178 gap is now reconciled (2026-10-01, read from `docs/NBASeriesResults.xlsx` directly):** the sheet's Game-7 rows are 158 NBA + 1 BAA + **18 ABA** = 177, and it stops at the 2026 conference semifinals, so the live table's 178th is the 2026 Finals Game 7 — which makes the archive **160 NBA/BAA + 18 ABA**, matching nba.com's published 160 Game 7s to the unit. The sheet carries a `League` column the loader dropped, so league is recoverable without any scraping, and the sharing epic's 178-based route list is unchanged (all 178 stay in the archive; only the *insight denominators* become league-filtered).
- Source access goes through one documented port with two fetch operations, adapters selected by environment variable, with the spreadsheet adapter as the guaranteed floor. The spike (decision record at owner review; its measurements are authoritative) ruled fantasy Fantrax out — its endpoints return fantasy point totals and playoff configuration, never real home/away game scores — and kept it recorded as rejected rather than silently dropped. The unkeyed public nba.com route passed per-game scores, series-status derivation, and historical depth; one keyed real-data provider is the unprobed alternate whose key becomes a CI secret and a stated tier/cost decision. **Clarified in Story 2.4:** the route actually shipped (`leaguegamelog`, unkeyed with the spike's six browser-like headers) needs **no key at all** — the keyed-provider sentence remains Story 2.1's open alternate, not an obligation Story 2.4 took on.
- Adapter hazards the spike measured, which Story 2.4 must inherit: derive the series year from the game's calendar year, never the feed's season identifier; derive game numbers from date order within the matchup, never the game-id suffixes; the matchup-string home/away marker carries a trailing period, so naive splitting shatters real series; pre-2003 first-round series were best-of-5 — "every series has seven rows" is this archive's selection, not a source rule, so feed validation must handle 3–5-game series; requests need browser-like headers plus an nba.com referer, and with rate limits unmeasured on a Cloudflare-fronted route that 403s guessed paths, assume a hostile cadence with backoff; no working endpoint returns a playoff round name (the bracket feed is retired) — the round-vocabulary gap the adapter must close; and the in-season leg stays unproven until re-run against a live 2027 bracket. **Inherited in Story 2.4's shipped adapter, each pinned by `tests/pipeline/nba-com.test.ts`:** calendar-year and date-order rules; the ` vs. ` period with either-row-first merge; the Game-7-only selection (which excludes pre-2003 best-of-5 shapes as "in flight" for free); the spike's six headers verbatim, one request per run, 25 s timeout and 3-attempt `[1000, 4000]` backoff with terminal messages naming the URL and refusing a silent `manual_csv` fallback; chain-depth round labels for the retired bracket feed; and the unproven legs — live reachability and whether the feed's numeric `TEAM_ID` agrees with `teams.id` — deferred to the owner-run `scripts/probe-nba-com-adapter.mjs` (Decision 12), the adapter itself resolving identity only through the port's abbreviation→`teams.id` resolver.
- Server code follows the Edge Function runtime convention, but third-party SDKs are imported through a prebuilt-types CDN rather than the package registry that resolves against this repo's lockfile — the CI type-check step is not hermetic and depends on network egress. No local Deno by owner choice: the first evidence the check can produce is a CI run, and the docs must say so plainly; the check step must also ship green (narrow the error catch in the same commit) and echo its resolved file count so an under-covering glob stays visible.
- Pipeline runs as scheduled CI workflows executing scripts under the pipeline scripts directory. The dry-run preview (Story 2.3 as built, and what epics.md:352's intent needs) is *no writes at all* — the plan is computed and asserted in memory, printed, and the run exits — because a client over PostgREST cannot open a transaction and roll it back; the atomicity the epic asks of a write comes instead from one `SECURITY DEFINER` RPC per operation (migration 00015), so a birth or a completion is one statement and either wholly lands or wholly fails. Any directory left unchecked by the local gate is recorded explicitly rather than quietly passing. The legacy spreadsheet loader that still writes to an archived table is repaired or formally retired in the runner story, since the floor adapter descends from it — retired in place: `supabase/scripts/load-games/main.py` deleted, with the retirement stated in `docs/CURRENT_DATA_MODEL.md`.
- Insights refresh triggers on an offseason run or a run that fills a winner (that write *is* the active→archive transition); the client keeps reading only the cache table.

## UX & Interaction Patterns

- With nothing pending, the picker shows an empty, non-breaking Active group carrying the established empty-state line ("No active series right now — the next Game 7 is coming.") and an onward link to the archive.
- Active versus Historical separation is visible to users but has no stored flag: a series enters the Active group because it has six score rows and no winner, and leaves it on the single write that fills the winner.
- The pending-Game-7 highlight on the home surface is a rendered block, not a route; this epic proves only that the data reaches it. Its visual treatment, copy, accessibility floor and responsiveness belong to the sharing epic.
- Verification exercises the derivation with real data shapes rather than faked status fields, and notes the picker query is unfiltered — a seeded row is live to every visitor the instant it exists, so drill data is inserted deliberately.
