## Boundaries & Constraints

**Always:**
- Keep the three keys and their JSONB member names exactly as the client declares them (`InsightsPage.tsx:7-24`): `game_6_winner_stats{total_game_sevens, game_6_winners_won, win_rate}`, `home_team_stats{total_game_sevens, home_team_wins, win_rate}`, `avg_point_differential{average, median, max, min}`. The page prints `win_rate` and then appends `%` (`:110`, `:136`), so `win_rate` is a **percentage** (seed `62.5`), not a fraction.
- Population = archived series (`winner_team_id IS NOT NULL`, AD-4) and, within each, the **game 7 row** (`game_number = 7`) — that is what all three cards' copy claims ("X out of Y Game 7s"). Margin is the absolute point difference (`avg_point_differential.min`/`max` are positive in the seed). Median = mean of the two middle values on an even count.
- The population is **league-filtered, and one filter serves all three cards**: `game_6_winner_stats`, `home_team_stats` and `avg_point_differential` all count `league IN ('NBA','BAA')` archived Game 7s. `home_team_stats` needs no separate venue test, because **`00016` rewrites the game-7 row of every NBA/BAA archived series (sides and their scores together, `winner_team_id` untouched) and the pipeline writes game-true venues from here on — so the league filter *is* the "this venue is real" marker** (Call 2, 2026-10-01). Rows the marker does not cover: the 18 ABA series, where `home_team_id` is still the series winner and a home-team statistic would yield a fabricated 100%. After Tier B the population is the 160 NBA/BAA Game 7s plus every series the pipeline writes, and `home_team_stats` must land at **117 home wins of 160** (nba.com's published 117–43 over the same set) — if the RPC's number is not 117, the venue curation or this story's filter is wrong, and that is a stop, not a tolerance. **[Split 2026-10-03 under the elicitation pass, P3, because the population differs before production and after it: the numerator is 117 in both readings, the denominator is 159 on U11's fixture and 160 on production. So the rehearsal's stop is "`home_team_wins` is not 117, or `total_game_sevens` is not 159" and the owner's post-apply stop is "not 117 of 160" — neither reading may be tested against the other's denominator, and both stay stops rather than tolerances.]**
- Refresh runs **after** the write phase, never before, and writes through `service_role` only. `updated_at` is set by the writer (the column has a `DEFAULT` but no trigger). **[Qualified 2026-10-03 under the elicitation pass, P2: "after the write phase" governs a run that has one. U10's operator path has no write phase — it refreshes and exits — so the ordering rule is vacuous there rather than violated, and the `service_role`-only rule binds both paths identically. Nothing in this clause licenses a refresh before a run's own writes land.]**
- Every run stays idempotent (AD-5): recomputing over an unchanged archive yields byte-equal payloads. **[Narrowed to what is actually invariant, 2026-10-03 under the elicitation pass, P7: `insight_value` is byte-equal; `updated_at` is expected to move, because the RPC sets it and that is the column's purpose. A test that compares whole rows goes red on a correct refresh, and the wrong fix for that red is dropping `updated_at` from the write.]**
- The refresh is **one RPC call whose three writes land in one statement** -- there is no client path that can leave the page showing two fresh cards and one stale one.
- **The arithmetic is exercised on real scores before any production run** (U11): the rehearsal builds its fixture from the committed source sheet joined to the committed curated CSV, and the three payloads are asserted against values measured from that same join. The existing synthetic fixture does not count as exercising them.
- A refresh failure terminates the run non-zero, naming what failed, like any other pipeline step.

**Never:**
- No change to `InsightsPage.tsx`, its copy, its decimal formatting, or its metric set (FR-18 / Story 5.1 owns wording). No new computation in the browser (AD-8). No intermediate data layer in `src/db/supabase.ts`. **[Exception authorized 2026-10-02 by owner decision U4: this story appends the one sample-set footer sentence at the foot of the page. It changes no card's copy, no decimal formatting, and no metric — it states the population the existing metrics already count, from a cached field — and reading a cached number is not computation in the browser.]**
- No metric derived from a date, a season window, or `created_at` (AD-4 and the frozen no-phase-from-dates rule); no code branches on `series.status`, which no longer exists.
- No edit to `00015`'s existing RPCs, and no write to `series`/`series_game_scores` in this story.
- The agent never applies a migration or writes production data. **[Enumerated 2026-10-03 under the elicitation pass, P11, because the story now has three owner steps and this clause named one: the agent hands over (1) `npx supabase db push`, (2) the `--refresh-insights` run (U10), and (3) the anon-role read-back of the three rows — exact lines in Verification — and F7 closes on (3), not on (1) or (2). Naming only "the run command" here read as if the ordinary pipeline run completed the story.]**

## Design Notes

Mechanism calls this spec makes so implementation does not have to re-decide them. None of them changes a frozen rule.

- **RPC shape.** `public.pipeline_refresh_insights_cache()` in `supabase/migrations/00017_pipeline_insights_refresh.sql` — **no arguments** (so there is nothing a caller can skew and no way to pass a population in), `RETURNS jsonb`, `LANGUAGE plpgsql`, `SECURITY DEFINER`, `SET search_path = public, pg_temp`, then `REVOKE ALL … FROM PUBLIC, anon, authenticated` + `GRANT EXECUTE … TO service_role` — all copied from `00015:40-49` / `:190-194` / `:353-361`. The returned object carries the population and the three counts, so the run's report line prints what the server wrote instead of re-reading the table.
- **One statement, three rows.** A single population CTE (`winner_team_id IS NOT NULL` AND `league IN ('NBA','BAA')` AND `game_number = 7`), then one `INSERT … VALUES` of three rows with `ON CONFLICT (insight_key) DO UPDATE SET insight_value = EXCLUDED.insight_value, updated_at = now()`. That is what makes "all three keys, or none" true rather than a hoped-for sequence of client calls — and it is why the RPC sets `updated_at`: the column has a `DEFAULT` and no trigger (`00001:66-72`).
- **Metric expressions.** Median is `percentile_cont(0.5)`, which *is* the frozen "mean of the two middle values on an even count". Margin is `ABS(home_score - away_score)`. `win_rate` and the two margin decimals round to 2 places; `max`/`min` stay integers. An empty population writes `total_game_sevens: 0` with zeros alongside — never a division, never `NaN` in JSONB.
- **Sink member.** `refreshInsights()` on `PipelineSink` (`writer.ts:25-32`), one `.rpc()` call, error text in `writer.ts:100-126`'s `throw new Error('<op> failed …')` form, plus `birth`'s second-throw convention (`:112-114`): a `null` census from a RPC that declared `RETURNS jsonb` throws rather than printing an empty report line. It returns the census so both callers — the completion-triggered path and U10's `--refresh-insights` path — share one implementation rather than one plus a duplicate.
- **The footer lives in a module, not in JSX.** `src/lib/insights.ts` exports `sampleSetSentence(totalGameSevens: number): string`; `InsightsPage.tsx` renders it between `:213` and `:214` inside a `<p className="text-sm text-on-muted">`. A separate module is what lets a test import it and hand it a number that appears nowhere in the cached fixtures — the cheapest available proof the sentence is not a literal — and it keeps the page doing no arithmetic (AD-8: reading a cached field and formatting a string is not computation of a metric).
- **Ceiling and migration share a commit.** `rehearse-migration-00014.mjs:206-217` fails the run on a `00017*` file while `COVERED_THROUGH` is still 16, so the bump at `:98` lands with the new file; Story 2.8 established the rule in that file's own header note.
- **U11's fixture mechanics live in one place: the `scripts/rehearse-migration-00014.mjs` task** (owner-approved dedupe, 2026-10-03 — the seeding rule, the after-the-replay placement, the venue-true game-7 rows, the unordered-pair join and the slot-sensitivity argument are stated there once, not four times). The only facts kept here are the two decimal readings, because they're the ones a reviewer will otherwise mis-compare: the fixture's home `win_rate` is **73.58** (117/159) where production reads **73.13** (117/160) — same numerator, different denominator, and the page's `toFixed(1)` prints 73.6 against 73.1. Both are correct; neither is a drift finding.
- **What the run's print can honestly say.** The `AdapterRunReport`-style line names the population the server counted, and it prints **only on the branch that refreshed** — the frozen offseason row of the I/O matrix runs the adapter's own report with zero writes, and a "cache refreshed" line there would be a false report about a run that did nothing.
- **Flag and `--dry-run` are mutually exclusive by validation, not by ordering.** U10's `--refresh-insights` must not be reachable through `--dry-run`: the dry-run contract (`run.ts:225-228`) is "zero writes", and a refresh is three. So the refusal is a `PipelineRunError` in the same try block as the other flag guards, ahead of `requiredEnv` at `:185-186`, and `run.ts:146`/`:175` already refuse unknown and misplaced flags, so an operator typo fails loudly instead of writing. `--refresh-insights` is a bare flag, so it joins `unknownFlag`'s literal at `:97` next to `'--dry-run'` — not `ADAPTER_FLAGS` (`:53-56`), which exists only to place `--name=value` flags per adapter, and the refresh path never reaches adapter selection.
- **The flag path is a short-circuit, not a mode.** It returns after one RPC and one log line; it does not set a flag that the normal pipeline then branches on in four places. Everything downstream of `run.ts:189` (`readTeams`, the adapter legs at `:202-203`, `readCurrent` at `:219`, planning, the write loops) is simply not reached — which is how the frozen I/O row's "no series row read or written" is enforced by structure rather than by care.
